AL Dev Toolbox - design system - step 2

Core component library

Every component in every state, built only from the step-1 tokens: buttons, form fields, cards, tabs, status pills, BC activity-indicator cues, data tables, overlays, the loading / empty / error triptych, page chrome and code affordances. Everything is BC-square - containers and controls share the same 2px shape language - and the teal focus ring is the same one everywhere. Light and dark render side by side; the two panels are the same markup under two theme scopes.

Spec

Files

  • components.css - the shipped component layer. Depends on tokens.css only; contains no raw hex.
  • foundations.css - spec-sheet chrome for this page (.doc, .panel, .states, .port), not shipped.

State convention

  • Real states use :hover, :focus-visible, :active, [disabled]. Every one of those also has a forced twin - .is-hover, .is-focus, .is-active, .is-disabled - so this sheet can show them at rest. The twins are display aids; the Blazor port only needs the pseudo-classes.
  • Component-owned state classes that ARE shipped: .is-selected, .is-checked, .is-indeterminate, .is-on, .is-open, .is-sorted, .is-copied, .is-dismissed, .btn--loading, .field--invalid.
  • Focus is never removed - outline: var(--focus-ring) + outline-offset: var(--focus-offset), one ring for buttons, inputs, tabs, menu items, cards and sort headers.

Rules this layer enforces

  • One .btn--primary per page. Everything else is .btn, .btn--ghost or .btn--danger.
  • A list is never a bare table: it is always loading, empty, error or populated. Empty states carry exactly one primary action.
  • Read-only and calculated inputs are filled and borderless (BC behaviour); numerics right-align with font-variant-numeric: tabular-nums.
  • Density is inherited, not per-component: wrap a region in .u-compact. .data-table--compact exists for tables that must be dense inside a balanced page.
  • One status language: status is always a coloured keyline in a --bar-* colour. Rows in tables and row-lists take it on the right edge plus a leading glyph (--edge); cards, detail headers and inline text take it on the left, as a squared .status-pill tag. Never both in one place, and never a rounded outlined lozenge - pills are square like every other control.

Tokens added in step 2

  • None. Every value resolves from tokens.css. Since step 1 that file also gained the BC control tokens (--r-control, --r-badge, --input-*, --label-leader), the fifteen --bar-* status-indicator tokens used by --edge, and the --cue-* tokens for BC activity tiles - all in both themes.

Icons

  • Inline SVG placeholders carrying data-lucide="name" (plus, chevron-down, chevron-right, more-vertical, search, check, x, alert-triangle, info, copy, inbox, rotate-ccw, arrow-up, arrow-down). Swap for the vendored Lucide sprite at port time; sizes are 16px in .btn, 14px in .btn--sm, 12-13px in pills.

JavaScript

  • Interaction on this sheet is class toggling only (menu open, card select, tab pick, toast dismiss, copy). No framework, no dependencies - the port replaces these with Blazor handlers on the same class names.
