AL Dev Toolbox - design system - step 7a

Content surfaces

The lighter end of the system: a long-form docs page with a constrained measure and an on-page TOC, the MCP "connect an agent" flow as numbered step cards with copyable snippets, and the two pages nobody designs until they are needed - 404 and a generic 500. Balanced density throughout; these are reading surfaces, not power tools. Both themes, live: copy buttons confirm in place, the token step generates, the connection test resolves.

Spec

Files

  • pages-content.css - docs, steps and full-page error states. Depends on tokens.css + components.css; no dependency on the power layer.
  • Page bodies PageDocs, PageMcpSetup, PageErrorStates (one component, kind="404" | "500"). ShellFrame body values docs, mcp-setup, 404, 500.

12. Docs / long-form

  • .docs / __main / __toc - prose column plus a 216px TOC that collapses out below a 1000px container. .docs__main caps at 74ch, not a pixel width: the measure stays right when a user bumps their root font size.
  • .docs__toc-list / .toc-link (+ --sub, .is-active) - a 2px rail with the active item taking a teal keyline and --primary-weak fill. Two levels only; a third means the page should be split.
  • .prose is the one place in this system that styles bare elements (h2, p, ul, table, code, blockquote, hr), because docs bodies come from authored markdown and cannot carry classes. Vertical rhythm is * + *, headings get a tighter lead-in to the paragraph that follows, and scroll-margin-top keeps anchor jumps clear of the sticky header. Modifiers: .prose__lead, .prose__meta, .prose__cap.
  • .codeblock + __bar / __lang / __name / __pre - a titled block with a copy button; --inlinebar is the single-line variant (an endpoint URL) with the button beside the code instead of above it. Tinting reuses the power-tool token classes .k .t .n .s .c, so a JSON snippet in docs and AL in Object Explorer are coloured by the same tokens.
  • .copy-btn.is-copied - the button swaps to a green "Copied" in place. No toast: feedback for a copy belongs where the click happened.
  • .note + --info / --warn / --tip / --danger - callouts on the .alert colour language but shaped for prose: icon, bold __title naming the kind, then __body. The title is what makes them work in greyscale.

13. Setup steps

  • .steps / .step + __n / __head / __title / __text / __body, capped at 82ch. .step.is-done swaps the number for a green check, .step--current takes a teal border plus a 3px inset keyline. A ::after connector joins the cards so four boxes read as one sequence.
  • Each step owns its snippet: the endpoint as an inline-bar codeblock, the env var, then the full mcp.json. Step 2 shows the one-time-secret pattern - the token, a copy button, and a warning that it will not be shown again.
  • Step 4 closes the loop from our side: a Test connection button with a loading state, resolving into a success alert that names the client, the server version and the tool count. A setup flow that cannot confirm itself is not finished.

14. Not found and server error

  • .errpage / __inner / __glyph (+ --warn, --danger) / __code / __title / __text / __path / __acts / __links / .errlink / __ref, capped at 56ch and centred on a calm --bg.
  • Both render inside the shell, so the nav and search are still a way out - a full-bleed error page that strips the navigation makes a wrong URL feel like an outage.
  • 404 states the path it could not resolve, then offers three real destinations (.errlink rows), including a search seeded with the fragment from the failed URL. 500 states that data is safe, offers a retry with a loading state, and carries the reference, timestamp and build that support will ask for - plus the line that we are already paged, so nobody writes a ticket for nothing.
  • Tone: no apology theatre, no mascots. It says what happened, whether it is the user's fault, and what to do next.

Tokens added

  • None. Everything here resolves from steps 1, 5 and 6 - the --code-* set, the semantic --*-bg / --*-text pairs, spacing and radii. If a content surface had needed a new token, that would have been a signal the palette was short, not that the page was special.

States rendered

  • Docs: active and idle TOC links, all four callout kinds, code block default and copied, prose table, inline code, links (default and hover styling defined).
  • Steps: done, current, upcoming, generated-secret state, button loading (create token, test connection), success alert, and the failure guidance note at the bottom.
  • Errors: 404 with path and destination links (hover/focus defined), 500 with retry loading, support reference block, and the ghost-button tertiary action.
