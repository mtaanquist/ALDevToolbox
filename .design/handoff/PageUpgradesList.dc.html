Spec

Files

  • UpgradesListBody.dc.html owns the page: head, view switch, Open and Archive. Props view (open | archive | fleet), kind (populated | loading | empty), compact.
  • PageUpgrades.dc.html still owns the fleet table and its sheet is unchanged. New prop embedded: drops its own head, makes "Move dates..." outline so "New upgrade" stays the only primary, uses the app's labels ("Start update...") and adds "Add to upgrade..." as a button. "Change the next version..." goes first in the More menu, the filter narrows to 190px and Refresh becomes icon-only, so the command row stays one 48px line at 1440px.
  • ShellFrame: body="upgrades-list" with bodyView. Upgrades stays current under Solutions.

Views

  • Open, Archive and Fleet are .pill-tabs on their own row under the head, so the switch never moves when the command row changes. Each tab carries its count. Archive is always present, even at 0.
  • Subtitle is computed: "5 open, 11 environments booked for tonight." or "Nothing planned."

Open view

  • Upgrade (name, then "to 28.4 - slot"), Status, Environments, Checked, Planned, Created by. Sorted by the planned slot, nearest first.
  • Status uses .status-pill, as the brief asks, though components.css keeps pills out of table rows. Planned = queued, In progress = running, Updated = warn (checks outstanding). Done only appears in Archive.
  • The breakdown uses words with tone on the counts that need action: running in --info-text, failed in --danger-text, the rest plain. Checked lines are counted as updated here and shown in the Checked column, so no line is counted twice.
  • Checked: "3 of 8" and a small <progress>; "-" while the upgrade has no environments.
  • Row menu: Open, Mark done..., Delete. Delete is disabled once anything has been sent, with the reason in its tooltip.

Archive view

  • Upgrade, Target, Environments (failed count in danger), Closed (when, by whom), Created by. Row menu: Open, Reopen. No selection, no primary.
