AL Dev Toolbox - design system - step 1

Foundations: the token layer

Every colour, type, space, shape, motion and density decision in the toolbox, as CSS custom properties in one tokens.css. Light and dark are both first-class and rendered side by side. Contrast ratios below are measured in the browser at render time from the actual computed colours - nothing is asserted by hand.

Dark - derived

Spec

Files

  • tokens.css - the canonical token layer. Import it first in every later step; token names are now frozen.
  • foundations.css - styles for this reference page only, not part of the shipped component layer.

Theme wiring

  • Light lives on :root, [data-theme="light"].
  • Dark is emitted twice, byte-identical: @media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) } and :root[data-theme="dark"], [data-theme="dark"]. The non-:root selector is what lets both themes render on one page.
  • color-scheme is set per theme so native controls and scrollbars follow.

Colour tokens

  • Brand: --primary, --primary-strong, --primary-stronger, --primary-weak, --primary-weak-strong, --on-primary, --on-primary-strong, --primary-ink.
  • Neutral: --bg, --surface, --surface-2, --surface-sunken, --border, --border-strong, --border-input, --ink ... --ink-4.
  • Semantic: --success, --warning, --danger, --danger-strong, --info, each with -bg and -text.
  • XLIFF: --st-untrans, --st-fuzzy, --st-trans, --st-final, each with -bg and -text.
  • Charts: --chart-1 ... --chart-12. Code accents: --code-type, --code-num.

Contrast decisions

  • --primary #00B7C3 carries white at only 2.5:1, so filled primary controls use --primary-strong #008089 with white (4.7:1). #00B7C3 remains for active indicators, selected borders and fills where ink is --on-primary.
  • #00B7C3 is also only 2.5:1 against white, so the focus ring has its own --focus-color (#008089 light, #5AD8E2 dark) - --focus-ring 2px + --focus-offset 2px everywhere, --focus-halo (inner --surface, outer focus hue) when the ring sits on a coloured fill.
  • The same 3:1 caveat applies to --st-trans (#00B7C3) and --info (#75B5E7): both are pill/large-fill colours paired with their -text variant, never thin marks or 1px boundaries. Use --primary-strong / --info-text for icons and rules.
  • --border-input #87929F measures 3.1:1 on --surface (3.7:1 dark); --border and --border-strong are decorative hairlines and are not held to 3:1.
  • BC sentiment hues (#9F9700 mustard, #EB6965 coral, #35AB22 green) are fills only; words use the darkened --*-text variants, all >= 4.5:1.
  • Dark theme lifts teal to #2CC8D4 / #5AD8E2 and pairs it with dark ink #06272B rather than white.
  • --ink-4 is intentionally ~3.9:1: micro-labels and non-essential meta only, never body copy.

Aliases kept for the port (retired)

  • The migration is finished, so the alias block is gone from tokens.css. It mapped --blue* onto the primary ramp, --good* onto --success*, --error-text onto --danger-text, and --sans / --mono onto --font-sans / --font-mono, so pre-migration CSS kept resolving while it was ported.
  • The blue ramp collapsed onto --primary-ink rather than --primary, because those names were used for foreground and --primary is 2.5:1. That flattening is why the aliases were always meant to be temporary: per-site accent-vs-text distinctions only come back once a surface names the semantic token it actually means. Every surface now does.
  • --danger, --info, --st-*, --r*, --shadow*, --nav-w, --top-h, --shadow-color, --code-type, --code-num keep their names with new values.

Density

  • Balanced default: --control-h 32, --control-h-sm 26, --control-h-lg 40, --row-h 40, --row-h-head 36, --cell-pad-x 12.
  • .u-compact re-points those to 26 / 22 / 32 / 28 / 26 / 8 and shrinks --space-3, --space-4, --text-base, --r. Scope it to a tool region (grid, source viewer, diff) - it inherits, so components need no compact modifiers.

Shape and form controls (matched to the BC client)

  • One shape language, square like the BC client: --r-sm 2 / --r 2 / --r-lg 3 / --r-xl 4 for containers, --r-control 2 for buttons, inputs, selects, checkboxes and lookup buttons, --r-badge 2. A card edge never disagrees with the button inside it. --r-pill is the only curve - status pills, avatars, progress bars.
  • --input-bg, --input-bg-readonly (filled, borderless - BC's calculated-field look), --input-bg-disabled, --input-border, --input-border-hover, --input-border-focus, --label-leader (dotted label-to-control leader).
  • Numeric fields right-align; assist-edit ... attaches to the field's right edge sharing its border.

Classes introduced (reference page only)

  • .doc, .panel, .swgrid / .sw, .pill, .chartrow, .type__row, .space__row, .tile, .demo / .dbtn / .dinput / .drow. Step 2 introduces the real .btn, .field, .status-pill, .data-table layer.
