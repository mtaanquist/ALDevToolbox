MCP server

Expose the toolbox to AI clients over the Model Context Protocol

Connect an agent

Updated 2026-08-06Applies to toolbox 2.4 and laterServer version 1.3

The MCP server lets an AI client read your BC workspaces and run a subset of toolbox actions - browse objects, search the Cookbook, generate an extension - without leaving the editor. It speaks the same permissions as the web app: an agent can never see or do more than the signed-in user can.

Preview feature The MCP server is on for tenant CRONUS but still marked preview. Tool names and payloads can change between minor versions; pin a server version in your client config if you script against it.

What the server exposes

Nine tools, grouped by the surface they wrap. Read tools are always available; write tools require the matching role and are refused with 403 tool_forbidden otherwise.

ToolKindNeeds
list_objectsReadDeveloper
read_objectReadDeveloper
find_referencesReadDeveloper
search_cookbookReadAny signed-in user
generate_extensionWriteDeveloper + quota
run_pipelineWriteRelease manager

Connecting a client

Every client needs two things: the endpoint and a personal access token. The endpoint is per tenant and never changes; the token is yours, expires after 90 days, and can be revoked from your profile at any time.

https://toolbox.cronus.example/mcp

Add the server to your client's config file. The example below is the shape most clients use; see Connect an agent for the exact file path per client.

json mcp.json 
{
  "servers": {
    "al-dev-toolbox": {
      "url": "https://toolbox.cronus.example/mcp",
      "headers": {
        "Authorization": "Bearer ${ALDT_TOKEN}"
      },
      "pinnedVersion": "1.3"
    }
  }
}
Do not commit your token Read it from an environment variable, as above. Tokens carry your full permissions, including run_pipeline if you hold the Release manager role. A committed token is treated as compromised and revoked on detection.

Verifying the connection

Ask the agent to list objects in a workspace you own. A working server answers with object IDs; a token problem answers with 401 and a reason.

shell 
# expects a JSON array of objects for CRONUS.Customer
curl -sS https://toolbox.cronus.example/mcp/health \
  -H "Authorization: Bearer $ALDT_TOKEN"
Scope the agent to one workspace Pass workspace=CRONUS-Customer as a query parameter on the endpoint. The agent then cannot see other customers' code, which is usually what you want on client work.

Rate limits and quotas

  • 120 requests per minute per token. Over the limit the server answers 429 with a Retry-After header; well-behaved clients back off automatically.
  • Write tools count against your workspace quota, the same as generating from the web app. A blocked quota returns 409 quota_exceeded rather than failing silently.
  • Long reads stream. read_object on a large codeunit returns chunked results; do not set a client timeout below 30 seconds.

What's next

Shipping in the next two releases. Dates are intentions, not commitments.

  • Translator tools - read and propose XLIFF targets from an agent, with the same fuzzy-review flow as the web grid. Targeted for 2.5.
  • Piper merge assistance - ask an agent to explain a conflict hunk before you resolve it.
  • Per-tool roles - grant run_pipeline without granting the whole Release manager role.
