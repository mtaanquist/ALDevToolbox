Connect an agent

Four steps, about two minutes. You need the Developer role - you have it.

Read the docs
Check the server is liveLive A site admin enabled the MCP server for tenant CRONUS on 2026-08-04. Nothing to do here.
2 Create a personal access tokenExpires in 90 days Tokens carry your permissions. Name it after the machine you will use it from, so you can revoke one laptop without breaking the others. 
aldt_pat_7f3c_9K2mQx4LbT8vRn1sWd6Ey0Ap
 Copy it now This is the only time the token is shown. If you lose it, revoke it and create another.
3 Add the server to your clientVS Code Put the token in your environment, then add the server block to .vscode/mcp.json in the workspace, or to your user settings for every workspace. 
setx ALDT_TOKEN "aldt_pat_7f3c_..."
 json .vscode/mcp.json 
{
  "servers": {
    "al-dev-toolbox": {
      "url": "https://toolbox.cronus.example/mcp?workspace=CRONUS-Customer",
      "headers": { "Authorization": "Bearer ${env:ALDT_TOKEN}" },
      "pinnedVersion": "1.3"
    }
  }
}
4 Test it Reload the window, then ask the agent to list objects in CRONUS.Customer. We will confirm the handshake from this side. {{ testNote }} Handshake received from VS Code 1.99 - server 1.3, 6 tools offered, workspace CRONUS-Customer. You are connected.
Stuck on step 4? A 401 means the token did not reach the server - check the environment variable is set in the shell that launched the editor. A 403 means the token is fine but your role does not cover the tool the agent tried. Full list in Rate limits and quotas.
