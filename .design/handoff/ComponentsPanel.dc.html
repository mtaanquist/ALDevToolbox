5 - Status pills and badges.status-pill

One status language everywhere: status is a coloured keyline in a --bar-* colour. Rows take it on the right edge (section 6); pills take it on the left, as a squared tinted tag - not a rounded outlined lozenge, which was the only fully round, fully outlined object in an otherwise square BC-native UI. Pills are for cards, detail headers and inline text - anywhere status is one attribute among many. Table and list rows never use pills.

6 - Activity indicators (cues).cue

The BC activity-indicator pattern: a solid filled tile with a large plain number, a rule, and a drill-down chevron. Attention is expressed by the FILL, not a badge - .cue--attention turns the tile red and thickens the rule - so a screenful of cues reads at a glance. The whole tile is the link, and every cue carries a "last activity" line so a count always says how fresh it is. Use cues for landing pages (Admin, Site admin, Home); use .stat-card in section 10 where a wall of filled colour would be too loud.

7 - Data table.data-table--edge

Row status is a 4px coloured right edge plus a leading glyph in a .data-table__col-state cell - not a pill column. Three signals, none of them colour alone: bar colour, glyph shape, and the accessible name on aria-label + title. The bars use dedicated --bar-* tokens because the pill fills are too faint at 4px (--info measures 2.2:1, --border-strong 1.6:1). Both tables below use it - it is the default for every table in the toolbox. Row states come in families so class, label and glyph always agree: object diffs .is-new / .is-modified / .is-unchanged, runs .is-queued / .is-running / .is-succeeded / .is-failed / .is-cancelled, lifecycle .is-published / .is-draft / .is-archived, XLIFF .is-untranslated / .is-fuzzy / .is-translated / .is-final.
