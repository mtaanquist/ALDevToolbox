AL Dev Toolbox - design system - step 5

Form-centric page archetypes

Four form surfaces on the same tokens, components and shell: the signature generator with its live folder-tree preview, the admin edit form with audit history and the reusable JSON diff, the settings surface with sub-nav and its dangerous-setting treatment, and the auth card in four states. Every frame is a real 1440px desktop shell scaled with a fixed transform, so the shell's container queries still see a desktop. The forms are live - toggle module cards and watch the tree, break the ID range, delete and restore the template, switch settings tabs, press Generate or Save for the loading states.

Spec

Files

  • pages-forms.css - form archetype layout layer. Depends on tokens.css + components.css (+ shell.css for the framed pages). Layout only; every colour resolves from a token.
  • Page bodies: PageGenerator, PageAdminEdit, PageSettings, PageAuth. ShellFrame gained three body values (generator, admin-edit, settings); auth mounts without the shell.

Shared form scaffolding

  • .form-sec + __head / __note / __cap - the section band every long form is built from: a .section-label caps it, a hairline separates it from the next. Reused by all three in-shell archetypes.
  • .form-actions + __spacer / __note (and --sticky) - one action row shape: primary left, destructive far right, state note between them. Never a lone Save floating in whitespace.
  • .id-range + __sep / __count - the from/to numeric pair with a live ID count, used by the generator and by Settings > General.
  • .module-list, plus .module-card__row / __id / __deps extending step 2's .module-card: the whole card toggles (role="checkbox", aria-checked), the caption carries "+ N dependencies", and the disabled card says why it is unavailable instead of just greying out. .check-list stacks plain option checkboxes.

5. Generator with live preview

  • .gen - 1fr / 392px, collapsing to one column under a 1080px container (the shell root), because this page is often rendered inside a scaled frame or a split view. .gen__aside is position: sticky, which works because only .app__content scrolls in the shell.
  • .tree / .tree__row + __ico / __name / __meta, indented by an inline --d depth variable rather than nested markup, so the preview is a flat list the Blazor side can emit from one loop. Row kinds: --gen (generated extension: teal folder, medium ink), --group (static/grouping folder, muted), --file. .tree__legend / .tree__key names that distinction on screen instead of relying on colour memory; .tree--loading dims the tree while a generate runs.
  • The preview is genuinely live: module selection drives the folder list, the per-module ID window (from + 100 * index), Extensions: N and Dependencies: M (2 base dependencies + each module's own + 2 for the test app).
  • Validation is shown where it happens: .field--invalid + .field-error on Publisher (required) and on the ID range (must hold 100 IDs per module), and the range error also disables Generate and re-labels the note under it - the button never lies about why it is dead.
  • Generate is a full-width .btn--primary at --control-h-lg with .btn--loading; the note under it becomes the progress line. Loading is the only state that hides the label, so the button never resizes.

6. Admin edit form + audit history

  • .edit-col - single column capped at 900px; forms do not get wider than they can be read. The audit panel sits outside that column, at full content width: it is a log, not a form, and the diff lines are the one thing on the page that genuinely wants the extra characters.
  • .sub-rows + __head / __foot / __empty and .sub-row + __grip / __name / __val / __acts - the sortable child list. .sub-row.is-dragging lifts the row into --primary-weak with a shadow and .sub-row--drop is the 6px insertion marker, so drag state reads without a live drag. Grips are real buttons: keyboard reorder is possible, not decorative.
  • Delete opens .confirm-dialog--danger over a .modal-backdrop and names the blast radius ("41 workspaces were generated from this"). Confirming does not destroy the page: it becomes soft-deleted - a red .alert--danger, every control disabled, and the action row swaps Save/Delete for Restore. Soft delete is a state, not a redirect.
  • The JSON textarea parses on every keystroke; a parse error turns the field invalid and shows the parser message. It is the one field where a client can be certain, so it says so immediately.
  • .audit / .audit__entry + __sum / __time / __avatar / __what / __who / __caret / __body / __foot - reverse-chronological, one row per entry: mono timestamp, avatar, sentence, action pill. The whole row is the disclosure button and the caret rotates; the expanded body holds the diff plus request id, IP and whether the change came through the MCP server.
  • The diff is the reusable piece (the audit log reuses it verbatim): .diff + __bar / __name / __keys / __key / __chip / __body / __ln / __gut / __code. Line states .diff__ln--add / --del / --chg tint the row AND carry a 3px left keyline in the matching --bar-* colour AND prefix + / - / ~ in the code column - three signals, so the diff survives colour blindness and greyscale printing. Two gutters hold before/after line numbers; .diff--split is the side-by-side variant for long objects.

7. Settings with sub-nav

  • .settings / __tabs / __body / __aside - step 2's .header-tabs switches sub-pages (General, SMTP, Backups, Quotas, Tools, and a disabled Single sign-on), with a sticky context card and a legend for the danger treatment on the right.
  • .setting-list / .setting + __label / __name / __hint / __ctl - a 260px description column against the control, one hairline per row. Denser than .form-grid, because settings are read far more often than they are edited.
  • .setting--danger - the dangerous-setting treatment: --danger-bg fill, a 3px --danger-strong left keyline, danger ink on name and hint, and a mandatory .setting__lock line stating the consequence ("Asks for confirmation and is written to the audit log"). Shown on Maintenance mode, Restore from snapshot and Purge audit log - including the disabled-by-role case, which explains the missing permission instead of silently greying out.
  • Save shows .btn--loading in both the page header and the card footer, then a .toast--success in .toast-stack (fixed, bottom-right, dismissible, aria-live="polite"). The SMTP tab carries the paired failure: a loading test button that resolves into a real relay error.

8. Auth card

  • .auth (calm --bg page, centred) / .auth__card - 372px, --surface, hairline border with a 3px --primary top edge as the only brand flourish; __brand / __mark / __product / __head / __title / __sub / __fields / __foot / __legal, plus __or for the SSO divider and __ok / __ok-icon / __mail for the confirmation state.
  • One primary action per card at --control-h-lg, secondary routes as quiet .auth__links. Error state pairs a card-level .alert--danger (with attempts remaining) and a field-level .field-error; success state replaces the form rather than stacking a banner on it.
  • .auth__row / __col / __state are sheet scaffolding only - the app renders one card per route.

Tokens added

  • Four, all diff-only and in both themes: --diff-add-bg, --diff-del-bg, --diff-chg-bg, --diff-gutter. The keylines reuse --bar-succeeded / --bar-failed / --bar-draft, so diff, table rows and pills stay one status language. Nothing else was needed - the four archetypes are built from steps 1-4.

States rendered on this sheet

  • Default, hover (.is-hover on a sub-row and an audit row), focus-visible (tab through any frame), active, disabled (option checkbox, module card, SSO tab, purge button, every control on the soft-deleted form), loading (Generate, Save, Send test email), error (publisher, ID range, JSON parse, SMTP relay, bad credentials), empty (.sub-rows__empty is defined for a template with no modules), plus read-only (.input--ro) and the confirm dialog.
