AL Dev Toolbox - design system - step 6

Data-dense power tools

The three surfaces where BC developers actually spend the day: the XLIFF translation grid, the Object Explorer reading surface, and Compare. All three run at compact density - 28px rows, 26px controls, 8px cell padding - and all three scroll inside their panes rather than scrolling the page, so toolbars, grid headers and rails never leave the screen. Fidelity at density is the deliverable: the grid stays legible at 618 units, the code view tints AL from dedicated --code-* tokens, and the diff is the same block the audit history uses in step 5. Both themes, live: open a translation row, switch the status filter, toggle inline diff.

Spec

Files and density

  • pages-power.css - the power-tool layer. Depends on tokens.css + components.css + shell.css, and on pages-forms.css for .diff, which Compare reuses rather than redefining.
  • Page bodies PageTranslator, PageObjectExplorer, PageCompare; ShellFrame gained the translator / explorer / compare body values.
  • Compact density is applied by the page, not the shell: each root carries .u-compact, so a power tool is dense even when the surrounding app is balanced. Nothing hard-codes a height - --row-h, --control-h and --cell-pad-x do the work, so the Settings density switch changes these three tools and nothing else.
  • Two :has() rules flush the shell's padded content column for any page containing .pw (padding: 0, full height, no page scroll). The shell stays ignorant of which body it renders, and the power page does not need a shell variant.

Shared power-tool frame

  • .pw - a four-row grid: .pw__head (identity + primary actions), .pw__bar (filters and view switches), .pw__body (the only flexible row, minmax(0, 1fr)), .pw__foot (a 26px status strip). Every pane inside scrolls independently; the frame never does.
  • .pane + __head / __title / __count / __body / __sec / __sec-h - the rail and inspector chrome shared by all three tools, so the left rail in Compare and the tree in Object Explorer have identical headers.
  • .kbd / .kbd-hint - these tools are driven from the keyboard, so shortcuts are printed in the footer rather than hidden in a help dialog. Every hint names a real binding.
  • .pw-split (and --row) - the 4px pane resize handles, teal on hover, focusable so panes can be resized from the keyboard. The hit area is widened with a ::after to 8px without moving the 4px visual.

9. Translation grid

  • .tgrid declares --tg-cols once; .tgrid__head and every .trow consume it, so a column change is one line. The header is position: sticky inside .tgrid__scroll, which is the element that scrolls.
  • Virtual-scroll-friendly rows: a closed row is exactly --row-h (28px) with no wrapping - source and target clip with ellipsis - so row offsets are computable without measuring. The open row is a declared calc(var(--row-h) * 3), not auto. .tgrid__window is the windowing spacer, labelled with the visible range.
  • Status is the same language as everywhere else: a 3px .trow__edge keyline in the --bar-* colour plus a .status-pill in the --st-* pair - never colour alone. .is-untranslated / .is-fuzzy / .is-translated / .is-final.
  • .trow--editing - the target becomes a .trow__ta textarea inside a teal inset ring, with a live .trow__count against the XLIFF max length (--over when exceeded) and the three bindings that matter printed beside it. The source cell un-clips and wraps so it can be read in full while translating.
  • .trow__acts (accept / machine-translate / clear) is hidden at rest and revealed on hover, focus-within or edit - 618 rows of visible icon buttons is noise, but keyboard users still get them via :focus-within. Clear is disabled when the target is empty.
  • .tprog - one stacked bar plus a named, counted legend. The bar alone would be decoration; the counts are what a translator reports upstream.

10. Source / object viewer

  • .oe - var(--oe-left) 4px 1fr 4px var(--oe-right): tree, handle, code, handle, inspector. The two custom properties are what a drag would write, so resizing is a variable update rather than a layout rewrite.
  • .otree / .otree__row - flat rows indented by an inline --d depth variable (same trick as the generator tree, same reason: one loop on the Blazor side). .okind is a two-letter mono chip - TE / PE / TB / CU / RE - which scans faster than five icon shapes at 13px and needs no icon per AL object type.
  • .ftabs / .ftab - the open-file strip: 30px, teal top rule on the active tab, .ftab--dirty swaps the close glyph for an unsaved dot exactly like VS Code.
  • .codev - line grid of 52px gutter plus code, white-space: pre, no wrapping. Tinting is one class per token kind against dedicated tokens: .k --code-key, .t --code-type, .n --code-num, .s --code-str, .c --code-com, .o --code-obj. Keywords are slate-blue and types are BC teal, so AL reads as our palette rather than a borrowed editor theme. .is-current marks the cursor line in --primary-weak.
  • .sym / .symcard - the definition affordance: a dashed underline on hover, then a card with the signature, the doc comment, the declaring app and file:line, and the two actions that follow (F12 / Shift+F12) with their bindings on the buttons.
  • .olist / .orow - the object outline (fields, procedures, triggers) with a mono glyph per member kind and the AL type right-aligned. .refs / .refgrp / .refhit - find-references results grouped by file, each hit showing the source line with the match in a <mark>; collapsed groups keep a 7-hit result readable in a 264px pane.
  • .codev-foot - Ln/Col, language, encoding, indent, runtime. Borrowed habit, on purpose: it is where a BC developer already looks.

11. Diff / compare

  • .cmp - rail, handle, view. .cmp__view holds a per-file bar and .cmp__panes, which is two columns side by side and one column with --inline; the toolbar's pill tabs switch between them.
  • The diff block is reused verbatim from step 5 - .diff__ln--add / --del / --chg, the --diff-*-bg tints, the --bar-* keylines and the + - ~ prefixes. Three signals again, so a diff survives greyscale printing and colour blindness. Added here: .diff__ln--void, a hatched spacer that keeps the two sides aligned where one version has no line, and .diff__code mark for word-level tinting inside a changed line, which is what makes Text[30] to Code[20] readable at a glance.
  • .hunk - the @@ separator, repeated in both panes so the sides stay in step; .cmp__phead is sticky per pane and carries that side's ref chip.
  • .vsbar / .vs / .refchip - the version header: base and target labelled by branch, each with its short SHA in a chip tinted --danger-bg (base, what is being replaced) or --success-bg (target). The arrow states the direction, which is the one thing people get wrong in diff tools.
  • .crail / .crow - the file rail at 26px per row: status keyline, A/M/D glyph, RTL-truncated path (so the filename survives and the folder is what clips), and +/- counts in tabular mono.

Tokens added

  • Five, all code-related, both themes: --code-key, --code-str, --code-com, --code-obj and --code-bg (aliased to --surface in light and --surface-sunken in dark, so the code canvas sits below the chrome in dark without a second neutral). --code-type and --code-num already existed. Everything else - the XLIFF --st-* set, the --bar-* keylines, the --diff-* tints - came from steps 1 and 5 unchanged.

States rendered

  • Grid: default, hover (T003), selected (T013), being-edited (T007), fuzzy (T011, T017), empty target, disabled row action, loading (Save file), plus the sticky header and windowing spacer under scroll.
  • Viewer: active tree row, dirty tab, current line, symbol hover + definition card, active reference hit, collapsed reference group, hovered and idle resize handles, read-only badge.
  • Compare: added / removed / changed / unchanged / void lines, word-level marks, active file in the rail, all three file states, side-by-side and inline layouts.
  • Focus-visible is on every interactive element in all three - tab into a frame to walk the grid, the tree, the tabs and the handles.
